# Deployment Alerting

Deployment alerts are based on the Prometheus metrics exported from the structured deployment audit trail.

Example rules:

examples/monitoring/deployment-alerts.yml

Example Alertmanager routing:

examples/monitoring/alertmanager.yml

## Alerts

### NuxtDeploymentFailure

Severity:

critical

Triggers when a deployment-related failure event appears during the previous 15 minutes.

This includes events whose result is:

failure
failed
critical_failure

Recommended response:

1. Confirm the active release or blue-green slot.
2. Check the deployment audit trail.
3. Check application and reverse-proxy health.
4. Determine whether automatic rollback succeeded.
5. Follow the incident-response runbook.

## NuxtAutomaticRollbackTriggered

Severity:

warning

Triggers when deployment automation successfully performs:

automatic_rollback
blue_green_traffic_rollback

A successful rollback restores availability, but it still indicates that the attempted deployment did not complete normally.

## NuxtDeploymentMetricsMissing

Severity:

warning

Triggers when Prometheus cannot observe:

nuxt_deployment_audit_events

for ten minutes.

Investigate:

deployment metrics export
Node Exporter textfile collector
Prometheus scraping
filesystem permissions
audit log availability

## NuxtDeploymentFailureNewerThanSuccess

Severity:

warning

Triggers when the latest failure timestamp for an operation is newer than its latest successful timestamp.

This helps identify an operation whose most recently observed outcome remains failed.

## Alertmanager

The repository includes a minimal Alertmanager routing example.

The example deliberately uses a loopback webhook:

http://127.0.0.1:9099/alerts

Replace this with an organization-specific integration.

Possible production receivers include:

PagerDuty
Opsgenie
Slack
Microsoft Teams
email
custom incident-management webhooks

Credentials must be delivered through the deployment environment or secret-management system.

Do not commit receiver credentials to this repository.

## Validation

CI performs:

promtool check rules examples/monitoring/deployment-alerts.yml

and:

amtool check-config examples/monitoring/alertmanager.yml

The repository also runs:

tests/config/deployment-alerts.sh

to enforce the expected alert coverage and prevent credentials from appearing in the example configuration.

## Relationship to Metrics

The alert rules consume:

nuxt_deployment_events_total
nuxt_deployment_last_success_timestamp_seconds
nuxt_deployment_last_failure_timestamp_seconds
nuxt_deployment_audit_events

These are generated by:

scripts/deployment-metrics.mjs

and exported through:

scripts/export-deployment-metrics.sh

## Scope

These alerts focus on deployment operations.

Application availability, latency, HTTP errors, host resources, and business-level signals should be monitored separately.
